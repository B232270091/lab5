## Анхны хүсэлт

`B231234567` оюутныг идэвхтэй, `CS201` үзсэн гэж бэлдэж,
`CS313` хичээлийн урьдач нөхцөлийг `CS201` болголоо.
Бүртгүүлэх POST хүсэлтэд статус `201`, `result="OK"` гэсэн хоёр тусдаа oracle тавьсан.
`registrationID`-ийн яг дугаарыг шалгахгүй, эерэг тоо эсэхийг шалгана.
Эхний ажиллуулалтын 7 assertion бүгд амжилттай, exit code `0` гарсан.
Гаралт [results/newman-pass.txt](results/newman-pass.txt) файлд байгаа.

## Тестийн дизайн

Бие даан тестлэх функцээр `POST /registrations`-ийг сонгосон.
Оролтын сонголтуудыг ангилаад, анги бүрээс төлөөлөх утга авч,
доорх спецификациудыг бодит setup PUT болон POST хүсэлт болгоно.

| Сонголт | Эквивалент анги | Төлөөлөх утга |
| --- | --- | --- |
| Оюутны хүчинтэй байдал | Байгаа, идэвхтэй | `status: "active"` |
| Оюутны хүчинтэй байдал | Байгаа, идэвхгүй | `status: "inactive"` |
| Оюутны хүчинтэй байдал | Байхгүй | Setup-д үүсгээгүй, ажиллуулалт бүрд ялгаатай ID |
| Оюутны үзсэн хичээл | Урьдач нөхцөлийг бүрэн хангана | `["CS201", "CS202"]` |
| Оюутны үзсэн хичээл | Заримыг хангана | `["CS201"]`, шаардлага нь `["CS201", "CS202"]` |
| Оюутны үзсэн хичээл | Огт хангахгүй | `[]`, шаардлага нь `["CS201"]` |
| Хичээлийн хүчинтэй байдал | Байгаа | Өөрийн setup PUT-ээр үүсгэсэн хичээл |
| Хичээлийн хүчинтэй байдал | Байхгүй | Setup-д үүсгээгүй, ажиллуулалт бүрд ялгаатай ID |
| Урьдач нөхцөл ба үзсэн хичээлийн харьцаа | Бүгдийг үзсэн | Шаардлага `["CS201"]`, үзсэн `["CS201"]` |
| Урьдач нөхцөл ба үзсэн хичээлийн харьцаа | Огт үзээгүй | Шаардлага `["CS201"]`, үзсэн `[]` |
| Урьдач нөхцөл ба үзсэн хичээлийн харьцаа | Заримыг үзсэн | Шаардлага `["CS201", "CS202"]`, үзсэн `["CS201"]` |
| Урьдач нөхцөл | Шаардлагагүй | `prerequisites: []` |
| Хүсэлтийн бүтэц | Нэг талбар дутуу | `studentID` эсвэл `courseID` байхгүй |
| Хүсэлтийн бүтэц | JSON эвдэрсэн | `{"studentID":` |
| Setup-ийн үндсэн утгууд | Талбарууд орхигдсон | Оюутан `{}`, хичээл `{}` |

### Спецификаци

| Кейс | Нөхцөл ба төлөөлөх өгөгдөл | Статус | result | Нэмэлт oracle |
| --- | --- | ---: | --- | --- |
| T01 | Идэвхтэй оюутан, үзсэн `[CS201]`, шаардлага `[CS201]` | 201 | OK | registrationID нь эерэг тоо |
| T02 | Оюутан байхгүй, хичээл байгаа | 200 | ERROR_NO_STUDENT | — |
| T03 | Идэвхгүй оюутан, хичээл байгаа, урьдач хангана | 200 | ERROR_INACTIVE_STUDENT | — |
| T04 | Идэвхтэй оюутан, хичээл байхгүй | 200 | ERROR_NO_COURSE | — |
| T05 | Идэвхтэй оюутны үзсэн хичээл `[]`, шаардлага `[CS201]` | 200 | ERROR_PREREQUISITES | missing нь `[CS201]` |
| T06 | Үзсэн `[CS201]`, шаардлага `[CS201, CS202]` | 200 | ERROR_PREREQUISITES | missing нь зөвхөн `[CS202]` |
| T07 | Оюутан болон хичээл хоёулаа байхгүй | 200 | ERROR_NO_STUDENT | Давхар алдааны эхэлж буцах үр дүн |
| T08 | Идэвхгүй оюутан, хичээл байхгүй | 200 | ERROR_INACTIVE_STUDENT | Давхар алдааны эхэлж буцах үр дүн |
| T09 | Идэвхтэй оюутны үзсэн хичээл `[]`, урьдач нөхцөл `[]` | 201 | OK | registrationID нь эерэг тоо |
| T10 | studentID талбар дутуу | 400 | ERROR_BAD_REQUEST | — |
| T11 | courseID талбар дутуу | 400 | ERROR_BAD_REQUEST | — |
| T12 | JSON тасарсан: `{"studentID":` | 400 | ERROR_BAD_JSON | — |
| T13 | Оюутны болон хичээлийн setup-д `{}` өгнө | 201 | OK | Үндсэн active, [], [] утгууд; ID нь эерэг тоо |
| T14 | Үзсэн `[CS201, CS202, CS101]`, шаардлага `[CS201, CS202]` | 201 | OK | Илүү хичээл үзсэн нь саад болохгүй; ID нь эерэг тоо |

T07, T08-ын хүлээгдэх үр дүнг серверт хүсэлт илгээж тогтоосон:
оюутан байхгүй эсэх, дараа нь идэвхтэй эсэхийг хичээлийн оршин байхаас өмнө шалгаж байна.
Оюутан байхгүй үед түүний үзсэн хичээлүүдийг ангилах боломжгүй;
хичээл байхгүй үед урьдач нөхцөлийн харьцаа мөн тодорхойгүй.
Ийм хослолыг зохиомлоор өгөгдөлтэй мэт үзэхгүй, холбогдох сонголтыг хэрэглэгдэхгүй гэж тооцсон.
